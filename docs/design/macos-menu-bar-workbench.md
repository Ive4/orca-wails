# Orca-Wails macOS 菜单栏设计

本文保留早期工作台探索。当前布局以 [DESIGN.md](../../DESIGN.md) 为准。状态项和刘海面板共用原生任务详情、本地结构化待办、后台任务启动和 Bot 选择器。面板能处理一次性审批，其他审批可从详情打开原会话。

## 目标

把查看进度、处理等待输入、查看结果和发起下一项任务做成菜单栏内的完整流程。验收按实际操作路径进行。关闭 Orca 主窗口后，用户仍能从系统通知进入对应任务，提交回复，看到 Core 的回执，并返回当前列表。任务继续在原会话和工作区运行。

## 面板结构

| 区域 | 内容与交互 |
| --- | --- |
| 当前 | 等待输入和受阻任务排在最前，其后显示运行、监测和待确认任务。每行显示形状标记、任务名、工作区、状态文字和时间。系统通知或选中任务可进入面板内详情。 |
| 最近 | 查看过去 24 小时的结束任务与结果，从原工作区和 Agent 预填一项新任务。会话是否成功以 Core 提供的信息为准。 |
| 任务详情 | 显示工作区、Agent、状态、最后一条有效进展以及对应操作。按需展开更多对话或终端输出。保留「在 Orca 中打开」入口，定位原会话。 |
| 新建任务 | 默认填入最近使用的工作区和 Agent，提交前显示实际目标。输入任务指令后在后台启动。拿到启动回执后进入新会话详情。 |
| 更多 | 提供按工作区筛选与最近查看记录，并放置机器人和设置。设置页保留通知、开机启动、关于与更新及内核维护。 |

右侧猫标面板的工具栏放「当前」「最近」与三个图标。「新建任务」打开本地工作区和 Agent 选择器，并提供 Bot 对话入口。「打开窗口」唤回主窗，「更多」提供机器人和设置。右键菜单提供查看任务、打开 Orca 和设置。两个设置入口都跳转到主窗口的「设置 → Orca Wails」。任务状态与排序由左右入口共用。面板沿用透明猫标、原生材质和轻量状态图标，彩色用于任务状态。

## 左侧应用菜单

| 菜单 | 操作 |
| --- | --- |
| Orca-Wails | 关于、Orca Wails 设置、隐藏与退出。关于与更新和内核维护位于设置页。 |
| 编辑 | 撤销、重做、剪切、复制、粘贴和全选。由当前焦点决定可用操作。 |
| 工作区 | 快速搜索、新建工作区、连接官方 Orca 和导入。搜索与新建复用已就绪的本地 Orca 窗口。 |
| 会话 | 最多三项待处理任务、查看全部任务、新建 Bot 对话、最近结束与机器人。点任务直接定位原会话，重名项可看工作区。 |
| 窗口 | 最小化、全屏、关闭和唤回 Orca。「关闭 Orca 窗口」使用 ⇧⌘W，⌘W 继续用于 WebView 内的标签页。 |
| 帮助 | 打开配置文件、日志和数据目录。 |

左侧维护入口打开轻量原生窗口，复用右侧设置的通知、更新、启动与停止内核等操作。内核停止或主窗启动失败时，也可在这个窗口查看结果和恢复操作。导入、停止及其他会打断任务的操作由原生确认处理。原生设置可重新绑定打开或关闭 Orca 的全局快捷键。

## 任务详情操作

| Core 返回的能力 | 面板呈现 |
| --- | --- |
| 结构化问题 | 显示原问题、选项与当前会话。用户显式提交所选选项，成功后显示回执。 |
| 结构化审批 | 显示确切工具、操作内容、工作区和授权范围。支持「仅本次允许」与「拒绝」，具体动作受当前请求支持范围约束。回执确认后重新读取状态。 |
| 可回复的会话 | 阅读最近消息并追加指令。按 Core 能力显示是否可在当前轮运行中提交。 |
| 终端会话 | 先提供有限长度的当前屏幕和日志，只读呈现。对全屏 TUI、复杂输入、终端选区保留原会话入口。 |
| 已结束任务 | 显示最后响应和可用结果链接，支持以同一工作区和 Agent 新建任务。可按需展开本地 Git 工作区的未提交改动与只读 diff。 |
| 能力不明、会话断开或数据部分可达 | 显示最后一次读取的时间及连接状态。草稿保留，发送与审批禁用，恢复连接后重新读取请求并由用户再次确认。 |

通知的默认动作进入菜单栏任务详情。需要避免应用激活后面板被旧的窗口重开逻辑抢占。通知来源携带不透明任务 ID。Core 重启或会话消失时，回到面板并提示原任务不可达。通知横幅展示状态和任务名，详情和审批内容在面板里查看。

## Wails 实现顺序

1. **读任务。** 复用 AppKit 状态项、NSPanel 与 SwiftUI。扩展原生面板快照，列表从已有 `worktree.ps` 获取。Go 解析当前任务 ID 与实际会话的映射，再用 Core 的 `nativeChat.readSession` 或 `agent.read` 按需读取详情。通知回调显示同一个面板并选中任务。验收覆盖 6 类状态、长标题、历史、空态、部分数据、关闭主窗后进入详情。
2. **处理待办。** 对结构化会话按其能力接入 `agentSession.send`、`agentSession.respondToQuestion` 和 `agentSession.respondToApproval`。Go 在执行前验证当前 Core、会话及待处理请求身份。一次提交使用一个请求标识，显示「发送中」「已接收」「失败」或「结果待确认」。结果待确认时只查询原回执，请求过期后重新读取。保持草稿与原面板位置。验收覆盖成功、过期、断线和重复提交。
3. **启动与查看交付。** 接入 `agent.launch`，让工作区、Agent 和指令在面板内完成选择。接入结束任务摘要和近期历史，随后根据使用频率扩展日志、文件与 diff。通知与内核管理继续使用 Wails 已有入口。验收以从关闭主窗开始完成「读结果 → 新建任务 → 查看新任务状态」为准。

当前接入使用 `agent.read` 和 `terminal.list` 读取近期记录及终端预览，使用 `agent.launchReplay` 后台启动现有本地工作区中的任务。Go 负责与 Core 通信，SwiftUI 面板接收展示数据和操作回执。切换详情使用 160 ms 淡入并尊重系统「减少动态效果」。

追加消息的核对读取原操作 ID 对应的记录。启动核对按预留的会话或终端标识读取任务与标签页。核对能确认标签页已创建，是否接收指令单独显示。详情可见时定期读取，重连后立即刷新。
