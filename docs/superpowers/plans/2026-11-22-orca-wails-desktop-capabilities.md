# Orca-Wails 桌面能力接入任务清单

目标是逐项补齐八项桌面能力。每项先用锁定版本核对上游入口和缺口，再做一条能在目标平台独立验收的流程。开始下一项前，记录当前项的测试结果和仍需验证的平台。

## 当前进度

- [x] 核对当前工作区与锁定的上游源码。macOS ARM64 使用 `v1.4.268`，Windows x64 正式锁为 `v1.4.267`。macOS 的工作区浏览器和基础数据插件已有接入，Windows WebView2 已承载主界面。macOS 已支持导入官方 Orca 当前 Profile 的项目与历史。详见 [升级记录](2026-11-21-orca-v1.4.268-upgrade.md)。
- [x] 核对 macOS 开发基线。现有十个补丁可依序应用到校验过 SHA-256 的 `v1.4.268` 源码。Go 测试、`go vet ./...`、Python 测试及逐个运行的九个 Node 测试脚本通过。Cua transport 首轮有一项对新增 `connectionId` 的断言失败，独立重跑通过。工作区同时有其他改动，按启动任务时的快照重跑基线。
- [x] 完成首项配置导入的上游入口核对，拟定 macOS 单文件导入的设计与实施步骤。[设计草案](../specs/2026-11-22-orca-terminal-config-import-design.md) · [实施清单](2026-11-22-orca-terminal-config-import.md)
- 用户已将 05 远程串流、06 浏览器扩展、07 模拟器界面和 08 高级插件提到当前开发批次。01–04 保留在后续清单。
- 当前批次已用 macOS ARM64 的 `v1.4.269` 构建 Core，并通过 Wails 应用冒烟、Go 测试、`go vet ./...`、Python 构建脚本测试和九个 Node 测试脚本。
- 锁定源码上的 35 个定向测试通过。`tc:node` 和 `tc:web` 仍分别报 Cua RPC 和标签拖拽的类型错误，在同一源码移除本批三个补丁后复现。

## 推进顺序

| 顺序 | 能力 | 优先交付的用户流程 | 依赖或验证条件 |
| --- | --- | --- | --- |
| 05 | 远程串流 | 已配对客户端打开远端浏览器标签，显示画面并能点击、滚动 | 可用的远端浏览器提供方。消费官方远端流可独立验证，Wails 提供流需单独验收 |
| 06 | 浏览器扩展 | 在已验证的平台加载一个测试扩展，重启后仍可使用 | 对应的工作区浏览器及站点数据隔离。Windows 与 macOS 分别评估 |
| 07 | 模拟器界面 | macOS 打开一个 iOS 模拟器标签，看到画面并可点按 | Xcode 和 iOS Simulator。Android 另行验证 |
| 08 | 依赖桌面接口的高级插件 | 安装一个需要桌面接口的插件，走完启用、运行和禁用 | 拟支持的桌面接口及对应平台能力 |
| 01 | 配置导入 | 在设置中选择 Ghostty 或 Kitty 文件，预览差异后应用 | 首先用 macOS 验收。Windows 发布需要可携带定制 Web 资源的构建流程 |
| 02 | 语音听写 | macOS 用户按键开始和结束，文字回到当前输入框 | 麦克风授权、可用的转写后端和 Core 能力探测 |
| 03 | 多 Profile | 创建并切换两个本地 Orca Profile，重启后恢复选中项 | Core 的数据归属、桌面生命周期和 WebView 存储隔离 |
| 04 | Windows 内嵌浏览器 | 在工作区新建独立 WebView2 标签页，完成导航与关闭重开 | Windows 11 x64 和 WebView2 实机或具备桌面能力的 CI |

当前批次先从 macOS 验收。浏览器扩展按平台判断依赖，高级插件按其声明的接口判断依赖。

### 01 配置导入

- [ ] **01A — 手动导入终端配置。** 在 macOS 本机 Wails 设置中选择 Ghostty 或 Kitty 配置，预览支持和未使用的配置项，手动应用后重开应用。选错文件或取消时验证设置没有写入。复用上游 `src/main/ghostty`、`src/main/kitty` 和 `useTerminalConfigImport`。详见 [实施清单](2026-11-22-orca-terminal-config-import.md)。
- [ ] **01B — 补齐来源。** 核对并接入 Ghostty、Kitty 自动发现和引用文件，以及 Warp/YAML 主题预览。选中可用主题后验收保存，自动发现为空时验收手动选择。入口位于上游 `src/main/terminal-config-import` 与 `src/main/warp-themes`。
- [ ] **01C — 验证 Windows。** 用同一组配置样例验收 WebView2 文件选择、预览、保存和重开。配置导入所需的定制 Web 资源纳入 Windows 可重复构建流程。

### 02 语音听写

- [ ] **02A — 接通本机听写。** 复用 `src/renderer/src/web/preload-api/agents/web-speech-api.ts` 的听写会话和 `speech.dictation.*`。验证本机 Core 的能力、模型和麦克风权限，再接入当前编辑框。首次拒绝授权、无法加载模型和取消听写都要有可观察结果。
- [ ] **02B — 验证快捷键与会话清理。** 覆盖结束听写、焦点切换、关闭窗口和重开。转写结果只进入发起听写的输入框。按 Windows 的麦克风权限和运行时支持情况验证对应入口。

### 03 多 Profile

- [ ] **03A — 实现本地创建和切换。** 以 `web-orca-profiles-api.ts` 目前单 Profile 的接口为入口，核对 Core 的 Profile 索引、数据根和切换行为。验收 A/B 各自可创建项目、切换后可回到各自状态，并在重启后恢复选中项。
- [ ] **03B — 验证隔离和失败恢复。** 覆盖会话记录、浏览器登录态、任务入口、进行中的任务及配对状态，明确各自的归属。用副本验证已有单 Profile 升级、官方项目历史导入、打开目标 Profile 失败时恢复原 Profile。云端 Profile 之后依据上游认证能力单独验收。

### 04 Windows 内嵌浏览器

- [ ] **04A — 验证 Windows 构建及子 WebView。** 依据现有升级记录选择可验证的 Core，从 `window_windows.go` 和 `scripts/build-windows.ps1` 验证独立浏览器视图、单独的数据存储，以及定制 Web 资源如何复现。记录 WebView2 版本、窗口销毁结果和 ConPTY、Job 冒烟结果。
- [ ] **04B — 接入浏览器标签。** 沿用 macOS 的工作区标签协议和页面生命周期，补齐 Windows 的新建、导航、下载、工作树切换和窗口重开。用两个页面验收各自的导航状态、布局和焦点。验证网页与 Orca 主界面的原生消息隔离。

### 05 远程串流

- [ ] **05A — 消费远程浏览器流。** 核对上游 `stream-remote` 和 `browser.screencast` 的订阅能力。用已配对的官方远端打开一个测试标签，验收画面、点击、滚动、断线重连和切换标签后取消旧订阅。
- [ ] **05B — 验证 Wails 作为串流来源。** 对已实现的平台浏览器验证画面获取、输入路由、可见性与流结束。用两个标签和两个配对会话检查帧和输入只进入对应会话，窗口关闭后释放资源。
  - macOS 无头 Chromium 已接入 Core 串流。真实 Chrome 的双标签画面、点击、滚动和停止捕获测试通过。打包 Core 的两条加密订阅收到各自页面的画面，后台捕获后活动标签不变，点击落在指定标签。官方远端客户端的窗口关闭和重连仍待验证。

### 06 浏览器扩展

- [ ] **06A — 确定可支持的平台和 API。** 以 `web-browser-api.ts` 的 `extensions*` 占位方法及上游 `src/main/browser/extensions` 为依据。对目标平台的 WebView 版本验证加载、列出、启用与移除一个本地测试扩展，并记录支持的 Manifest 和 API。
- [ ] **06B — 接入扩展管理。** 接入 06A 验证成功的能力。验收启用后仅对批准的站点生效，关闭、禁用、重启和切换浏览器 Profile 后的行为符合预期。商店安装与其他 API 按平台能力分别列入验收。
  - macOS 15.4 及以上的本机 WebKit 标签可从配置加载解包扩展。用原生 WebKit 验证了站点授权、重启后的扩展存储，以及窗口重载时清理旧标签后重新打开。Windows、设置页管理和商店安装待验收。

### 07 模拟器界面

- [ ] **07A — 接入 macOS iOS 模拟器。** 核对 `src/main/orcad/host-runtime/orcad-emulator-bridge.ts` 和 Web `createEmulatorApi` 的差距。复用上游面板和已有设备会话，验收可枚举设备、打开标签、显示画面、点击及关闭后停止串流。覆盖缺少 Xcode、设备关机和断开。
  - 已接入 Wails 本机工作区的 iOS 模拟器标签、设备枚举与 JPEG 帧流，沿用面板现有的输入和关闭流程。分片 JPEG、取消、上游断流和地址校验用模拟 HTTP 流验证。已确认打包 Core 能报告缺少 `simctl`。当前主机只有 Command Line Tools，真实设备流及输入待验收。
- [ ] **07B — 验证 Android 模拟器。** 利用同一面板接现有 Android 后端。在安装 Android SDK 的测试环境验收枚举、画面和交互，记录 macOS 与 Windows 各自通过的范围。

### 08 依赖桌面接口的高级插件

- [x] **08A — 确定首个插件和接口。** 首版使用测试插件声明的 `contributes.statusBarItems`。已授权的插件 worker 可用 `orca.host.call('statusBar.update', …)` 更新自己声明的项。本机 macOS Wails 窗口订阅更新。
- [ ] **08B — 接入并验收接口。** 加入 08A 对应的宿主接口。验证安装、启用、实际调用和禁用后的资源清理。未声明权限、配对窗口和不支持的平台分别确认提示。保留现有基础数据插件的安装和运行回归。
  - 打包 Core 已用真实 worker 验证安装、授权、更新、拒绝未声明项、禁用和清理。Web 测试覆盖状态订阅、配对切换和连接中断后的恢复。其他桌面接口和 Windows 仍待验收。
