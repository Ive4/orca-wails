# 个人微信任务助手

## 目标

在个人微信私聊里查看 Orca 任务。Bot 等待用户输入、受阻或完成任务时，微信主动收到提醒。用户可以在手机上回答结构化问题或补充指令，任务在原工作区和会话继续。第一版覆盖本机 Orca-Wails 任务，复用任务面板已有的状态、权限和回执，在 macOS 完成首轮验收。

## 使用流程

1. 在 Orca-Wails「设置 → 任务通知 → 微信」开启连接。用自己的微信扫码，按微信要求完成确认。扫码后，在该 Bot 私聊发送桌面显示的一次性配对码。Orca 校验发件人与扫码账号一致，绑定该私聊。设置页显示连接状态、上次收发时间，以及「测试通知」和「解除绑定」。
2. 在微信发「任务」查看当前任务，等待输入和受阻放在前面。每条列出任务号、Bot 或任务名、工作区、状态与更新时间。「任务 A17」查看这项任务最近的进展、待处理问题或完成结果。
3. 任务首次等待输入或受阻时发送一条提醒，附简短原因和可用操作。每个可回复的问题版本分配独立的回复码。同一等待事项持续存在时只提示一次。
4. 用户回复 `A17-2 1` 选择选项，`A17-2 1,3` 完成单题多选，或按提示填入该问题允许的文字答案。分组问题在微信按顺序收集答案，最后一次提交给 Core。可追加消息的会话使用 `A17 补充 …`。当会话存在待处理问题时，引导用户使用该问题的回复码。
5. 微信区分「已提交，等待 Bot 继续」「该问题已变化，请查看最新版」和「提交结果待确认」。已提交的动作以 Core 回执为准。Bot 状态回到运行后，微信可通知「已恢复运行」。
6. Core 确认工作完成后，主动推送任务号、Bot 或任务名、工作区和简短结果。每次任务结束只推送一条。以 Core 提供的结果区分完成、失败和取消。

提醒示例

> **A17 · 前端 Bot 等待输入**
>
> 工作区「登录页」。页面已完成，测试缺少账号。
>
> 1. 使用模拟账号
> 2. 等待提供测试账号
>
> 回复 `A17-2 1`，或回复 `任务 A17` 查看详情。

## 第一版的操作范围

| 任务状态或请求 | 微信端能做什么 |
| --- | --- |
| 运行、监测、结束 | 查询进度。工作完成时自动推送结果。 |
| 本机结构化问题 | 回答单选、多选、分组问题，也可在支持「其他」的选项中输入文字。 |
| 可追加消息的本机会话 | 使用明确的「补充」指令。Core 拒绝追问时显示当前待处理项。 |
| 工具审批 | 显示任务和审批类型，提示在 Orca 原会话处理。微信执行审批留到后续确认。 |
| 终端交互或远程会话 | 查询状态与简短原因，提示在原会话处理。 |

第一版采用一个本机安装、一个微信私聊、纯文字。群聊和通过微信启动新任务留到后续讨论。默认发送任务名、状态和简要进展，详情通过任务号按需读取。完整会话、终端输出和凭据留在本机。

## 接入方式

| 方式 | 取舍 |
| --- | --- |
| Orca-Wails 直接接入腾讯 iLink | 在 Go 中实现扫码、自有账号授权、消息长轮询和发送。使用已有任务服务提交回复。部署随应用完成，需验证当前微信协议和主动通知。采用此方式。 |
| 本地运行 OpenClaw 中转 | 复用腾讯已发布的 OpenClaw 插件，另建本机桥接把入站消息与回复交给 Orca。适合隔离验证通道，正式使用会增加安装、账号状态和两个后台进程的维护成本。 |

微信连接由 Wails 后台生命周期管理，关主窗口后继续收发。应用或设备离线时，在恢复后重读当前任务，聚合离线期间仍需处理的事项，并发送尚未送达的任务完成结果。微信出站只使用授权账号与已绑定私聊。连接信息保存在本机的数据目录，限制文件访问权限，诊断日志只记录动作类型、状态和无敏感内容的标识。

工作区任务沿用现有状态轮询和状态比较。先验证真实 Bot 团队成员的后台会话是否出现在任务快照，并保留可回复的结构化会话 ID。未进入这张快照的团队任务补用 Core 的团队会话状态和待处理请求，同一会话合并为一项任务。

宿主记录短任务号对应的真实会话，以及每个回复码对应的会话、问题 ID 和固定版本。问题发生变化时，旧回复码返回过期提示。并行的分组答题进度按各自的回复码保存。入站消息去重，阻塞通知按任务、状态及问题版本去重，完成通知按任务执行与结束记录去重。若提交回执丢失，先读原请求的处理结果。尝试重新发送微信通知前先重读任务，过期通知直接丢弃。绑定解除后清除收发凭据，废弃旧配对码与任务回复映射。

## 验收

1. 先用自有测试微信验证官方扫码流程、文字收发和进程重启后的连接恢复。分别测试刚完成配对和**隔一夜未发新消息**时，微信能否主动收到阻塞通知。记录 Orca 检测到阻塞、微信接口回执和手机收到消息的时间。腾讯协议给出了会话上下文的回传方式，主动通知能否送达以实际测试结果为准。
2. 在关闭 Orca 主窗口的情况下，分别让一个普通工作区会话和一个实际 Bot 团队成员触发结构化问题。两种任务均可在微信查询、收到等待通知并回复。各自的原会话恢复运行，微信显示 Core 回执。待 Bot 完成任务，让手机在未主动查询时收到一条带结果摘要的完成通知。第 1 项通过、本项的原会话恢复与完成通知均验证后，完整版本验收通过。主动提醒未通过时，查询和回复可以作为预览，状态页明确标记提醒未通过验证。
3. 两个任务同时等待时，回复其中一个，另一个保持原状态。桌面先处理、旧通知回复、微信重复投递和 Core 回执丢失，都不会再次执行已完成的动作。
4. 未绑定的会话无法查询任务或提交回复。解除绑定后，旧会话、旧回复和旧配对码立即失效。
